Change a mod without losing your place.

A Minecraft launcher whose companion mod puts the mod list inside the game. Toggle something, press one button, and you are back on the same server about ten seconds later — instead of quitting to a menu, finding a launcher window, and hunting for the server again.

Nothing waiting.

Two halves, kept apart on purpose

Some changes happen now. Some happen next launch. The screen tells you which.

Mixing the two in one list would make both harder to trust — nobody should have to remember which rows apply immediately. So they get separate screens, and each says plainly which kind it is.

Applies next launch

Mods

Toggle anything in the instance. The footer counts what is waiting rather than pretending it has happened — and offers to spend the restart there and then, straight back into the server or world you were in.

Applies immediately

Resource packs

Switch a pack and the world looks different a second later. It runs through Minecraft's own commit path, so a change made here is indistinguishable from one made in the vanilla screen — including surviving the next launch.

Applies immediately

Frame times

F6 shows the slow tail rather than an average. An average frames-per-second is exactly the statistic a stutter hides inside; the 1% low is the number that moves when a setting actually helped.

When it stops starting

The launcher knows which mod set worked. The crash log does not.

The companion mod reports in once the client is up — Fabric resolved the list, every mixin applied, the window exists. Nothing outside the process can tell that apart from a game that died before the window opened. So when a launch fails inside the first minute without ever reporting, Loadout can name the last set that did start, and offer it.

It offers. It does not act.

Rewriting your mod list because a process exited badly is help that is indistinguishable from a bug. The diagnosis is a good guess, not a fact, so a person decides.

It stays quiet when it should

A game that ran an hour and then crashed did start, so its mods are not the answer. A failed start with the same mods as last time says exactly that, rather than sending you down the wrong path.

Rolling back is instant

Snapshots are lists of hashes and every file already lives in a shared store, so going back is relinking rather than re-downloading. No network, under a second.

Measured, not claimed

Pressing Play should not be the slow part.

A warm launch — everything already installed, nothing to download — used to spend about nine seconds in the launcher before Minecraft's JVM was even spawned. All of it was re-learning something already known.

8.9 s 1.3 s Launcher work before the game process starts, on a warm instance.
Identifying every JDK by running it 4421 ms → 40 ms
Checking 5057 assets already on disk 1939 ms → 0 ms
Re-fetching the Fabric profile 379 ms → 17 ms
Refreshing the Microsoft session ~2000 ms → once a sitting

The asset check built a fresh HTTP client per file — five thousand of them, each with its own thread — to ask the filesystem a question and then return without sending a request.

The overlay

One bad frame in a hundred is invisible in an average.

Sixty frames where fifty-nine take 10 ms and one takes 400 ms average out to something that looks fine — and the 400 ms frame is the entire problem. Change a memory setting or a collector preset, play for a few minutes, and watch whether the 1% low moves.

8.2 ms avg · 31.4 ms 1% low · 96 ms worst
121 fps · 1024 frames measured
G1 Young Generation + G1 Concurrent GC · 34 collections · 41 ms worst · 612 ms/min
3184 / 6144 MB heap

The collector line sits beside the frame line deliberately. A collection's duration is not a pause — ZGC does almost all of its work concurrently and can post long durations while nothing stopped at all. Long collections next to steady frames are a success, and would read as a problem if the two were reported apart.

What it cannot do

Why nothing hot-swaps a Minecraft mod.

This gets asked as a loader question — surely NeoForge, or Quilt, or one we write ourselves? It is not a loader question. There are three layers in the way, and only the first belongs to the loader.

Layer 1 · the loader

Every loader resolves mods at startup

Fabric, NeoForge, Forge and Quilt all build the mod list during bootstrap and never revisit it. This part really is a design choice, and a loader could in principle be written to read a jar later. It is also the only one of the three that could.

Layer 2 · the game

Minecraft freezes its registries

MappedRegistry.freeze() flips a flag, and every write after it throws Registry is already frozen. Blocks, items, entities, sounds, block entities — all of it. So any mod that adds content cannot be added late no matter which loader you use, because the refusal comes from Minecraft, not the loader.

Layer 3 · the JVM

Loaded classes cannot be restructured

A class the JVM has loaded can only be redefined in its method bodies — redefineClasses cannot add a method, add a field, or change a supertype. Mixins are applied as classes load, so a new mod's mixins can never reach classes the game already holds. Patched JVMs like DCEVM lift some of this; shipping one to players is not a launcher feature.

So could we write one that does?

For a narrow slice, genuinely yes — and it would not be a mod loader. Give each plugin its own classloader, let it hook only through our own API rather than by mixing into Minecraft, and forbid it from touching registries, and it can be loaded and dropped while the game runs. That covers HUD widgets, keybinds, commands, client automation and cosmetics.

What it does not cover is a mod that adds a block. Calling that "hot-swappable mods" would be the marketing answer; it is a plugin system, and worth building as one honestly rather than pretending the wall is not there. Loadout's answer is the other one: the restart is unavoidable, so make it cost ten seconds.

Getting started

Install

The launcher runs on Windows, macOS and Linux. The mod is client-side only — put it in any Fabric instance, and the halves that do not need a launcher work anyway.

Build the launcher

Java 25 is fetched automatically if the machine has none.

git clone https://github.com/ComplexKing/loadout
cd loadout && ./gradlew dist

Start the desktop app

It spawns the jar and drives it over a loopback API, so the command line stays a first-class way in.

cd app && npm install && npm start

Sign in and make an instance

A Microsoft account, a Minecraft version, and Fabric. Mods come from Modrinth and CurseForge in one search.

Press \ in game

The companion mod ships with the instance. F6 toggles the frame time overlay, and Mod Menu's Configure button opens the same screen.
