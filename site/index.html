Minecraft 26.2 · Fabric · Client-side

Change a mod without losing your place.

Loadout is a Minecraft launcher whose companion mod puts the mod list inside the game. Toggle something, press one button, and you are back on the same server about ten seconds later — instead of quitting to a menu, finding a launcher window, and hunting for the server again.

Two halves, kept apart on purpose

Some changes happen now. Some happen next launch. The screen tells you which.

Fabric decides what is loaded during bootstrap, before any mod's code exists — so nothing can add or remove a mod mid-session, and a launcher that implied otherwise would be lying. Resource packs are different: the game already knows how to rebuild its resources. Mixing the two in one list would make both harder to trust, so they get separate screens.

Applies next launch

Mods

Toggle anything in the instance. The footer counts what is waiting rather than pretending it has happened — and offers to spend the restart there and then, straight back into the server or world you were in.

Applies immediately

Resource packs

Switch a pack and the world looks different a second later. It runs through Minecraft's own commit path, so a change made here is indistinguishable from one made in the vanilla screen — including surviving the next launch.

Applies immediately

Frame times

F6 shows the slow tail rather than an average. An average frames-per-second is exactly the statistic a stutter hides inside; the 1% low is the number that moves when a setting actually helped.

When it stops starting

The launcher knows which mod set worked. The crash log does not.

The companion mod reports in once the client is up — Fabric resolved the list, every mixin applied, the window exists. Nothing outside the process can tell that apart from a game that died before the window opened. So when a launch fails inside the first minute without ever reporting, Loadout can name the last set that did start, and offer it.

It offers. It does not act.

Rewriting your mod list because a process exited badly is help that is indistinguishable from a bug. The diagnosis is a good guess, not a fact, so a person decides.

It stays quiet when it should

A game that ran an hour and then crashed did start, so its mods are not the answer. A failed start with the same mods as last time says exactly that, rather than sending you down the wrong path.

Rolling back is instant

Snapshots are lists of hashes and every file already lives in a shared store, so going back is relinking rather than re-downloading. No network, under a second.

Measured, not claimed

Pressing Play should not be the slow part.

A warm launch — everything already installed, nothing to download — used to spend about nine seconds in the launcher before Minecraft's JVM was even spawned. All of it was re-learning something already known.

The asset check built a fresh HTTP client per file — five thousand of them, each with its own thread — to ask the filesystem a question and then return without sending a request.

The overlay

One bad frame in a hundred is invisible in an average.

Sixty frames where fifty-nine take 10 ms and one takes 400 ms average out to something that looks fine — and the 400 ms frame is the entire problem. Change a memory setting or a garbage collector preset, play for a few minutes, and watch whether the 1% low moves. If it does not, the setting did not help.

8.2 ms avg · 31.4 ms 1% low · 96 ms worst
121 fps · 1024 frames measured
G1 Young Generation + G1 Concurrent GC · 34 collections · 41 ms worst · 612 ms/min
3184 / 6144 MB heap

The collector line sits beside the frame line deliberately. A collection's duration is not a pause — ZGC does almost all of its work concurrently and can post long durations while nothing stopped at all. Long collections next to steady frames are a success, and would read as a problem if the two were reported apart.

What it cannot do

The honest part.

It cannot hot-swap a mod into a running game.

Fabric resolves the mod list, loads the classes and applies every mixin during bootstrap. That is the platform, not a gap, and no amount of effort changes it. So the question is not whether a restart happens — it is what the restart costs. Landing back on the same server turns two minutes of menus into about ten seconds, and that difference is the whole feature.

Shader packs are a loader's concept rather than the game's, and the loader that reads shaderpacks/ does not run on 26.2's Vulkan path at all. Loadout installs them into the folder for whenever that changes. Rejoining a Realm is not supported either: quick play wants a realm id, and a rejoin that opens the wrong world is worse than one that admits it cannot.

Getting started

Install

The launcher runs on Windows, macOS and Linux. The mod is client-side only — you can put it in any Fabric instance, and the halves that do not need a launcher work anyway.

Build the launcher

Java 25 is fetched automatically if the machine has none.

git clone https://github.com/ComplexKing/loadout
cd loadout && ./gradlew dist

Start the desktop app

It spawns the jar and drives it over a loopback API, so the command line stays a first-class way in.

cd app && npm install && npm start

Sign in and make an instance

A Microsoft account, a Minecraft version, and Fabric. Mods come from Modrinth and CurseForge in one search.

Press \ in game

The companion mod is installed with the instance. F6 toggles the frame time overlay, and Mod Menu's Configure button opens the same screen.
